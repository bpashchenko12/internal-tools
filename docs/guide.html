Guide

Build a tool in the XM style

Every tool is a folder of plain HTML, CSS and JS. No build step, no framework, no login code to write.

Add your tool

  1. Copy tools/_template/ to tools/your-tool-id/ (lowercase, dashes).
  2. Edit index.html: title, data-title on the top bar, and your content. Keep the gate.js line first in <head>.
  3. Register the tool by adding an entry to tools.json: 
    {
  "id": "your-tool-id",
  "name": "Your Tool",
  "description": "One sentence, under 140 characters.",
  "category": "SEO & Marketing",
  "status": "prototype",        // prototype | beta | live
  "icon": "chart",              // see assets/js/shell.js
  "accent": "green",            // green | blue | amber | purple | red | dark
  "owner": "Your name",
  "path": "tools/your-tool-id/"
}
  4. Test locally: python3 -m http.server 8000, open http://localhost:8000, then run python3 scripts/check.py.
  5. Open a pull request. After review and merge the hub redeploys and the tool appears on the home screen as an app icon (the icon and accent colour you chose).

Style rules

  • Use assets/css/xm.css only. Colours, radius, shadows and sizes come from var(--tokens); never write a hex colour.
  • Font is Poppins. Smallest text is 12px (--fs-xs).
  • Primary actions are green .btn-primary; one per screen.
  • Page = .page + .page-head (eyebrow, title, one line of context, optional action).
  • Use cards, stats, tags, tables and tabs from this page before inventing anything new.
  • Your own CSS goes in tool.css, class names prefixed with your tool id.
  • Green = good/brand,"accent": "green", // green | blue | amber | purple | red | dark = bad/risk, amber = needs attention, blue = information.
  • Never put API keys or passwords in the repo or browser code. Fetch data on a server or scheduled job and commit sanitized JSON only.
